## 🔧 技术实现要点

### 1. 用户管理的业务逻辑

**买家管理：**
```
买家账户 → 可禁用/启用 → 禁用后无法登录、无法下单
         → 可删除 → 删除后清除个人信息，保留订单历史（匿名化）
         → 可查看详情 → 显示基本信息 + 订单统计 + 最近订单
```

**卖家管理：**
```
卖家账户 → 可禁用/启用 → 禁用后所有商品自动下架，无法发布新商品
         → 可删除 → 删除前警告：将同时删除所有商品和关联数据
         → 可查看商品 → 展开行显示商品列表，支持快速审核跳转
```

### 2. API接口设计（需后端配合）

```javascript
// 买家管理API
POST   /ops/buyers              // 获取买家列表
POST   /ops/buyers/{id}/toggle-status  // 切换买家状态
DELETE /ops/buyers/{id}          // 删除买家
GET    /ops/buyers/{id}/orders   // 获取买家订单列表

// 卖家管理API
POST   /ops/vendors             // 获取卖家列表
POST   /ops/vendors/{id}/toggle-status  // 切换卖家状态
DELETE /ops/vendors/{id}         // 删除卖家
GET    /ops/vendors/{id}/items   // 获取卖家商品列表
```

### 3. 前端状态管理策略

- 使用 `ref` 和 `reactive` 管理本地状态
- 操作成功后重新调用 `loadData()` 刷新列表
- 使用 `Message.success/error` 给用户反馈
- 关键操作使用 `Modal.confirm` 二次确认

## ⚠️ 注意事项

1. **删除操作的谨慎性**：删除用户是不可逆操作，必须二次确认，并在确认框中明确告知后果
2. **禁用操作的联动性**：禁用卖家时需同步处理其商品状态
3. **权限控制**：所有管理操作都需要运营人员权限验证
4. **错误处理**：网络请求失败时给出友好提示，不要暴露技术细节
5. **性能考虑**：列表数据量大时考虑虚拟滚动或分页加载
