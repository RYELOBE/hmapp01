# 系统核心模块设计与实现

## 概述

本文档详细阐述校园二手交易平台九大核心模块的设计与实现，涵盖业务逻辑、产品逻辑、技术架构、数据库设计及关键代码实现。系统采用前后端分离架构，后端基于 Spring Boot 3.3.5 + Java 17 + Spring Security + JJWT + MySQL + JdbcTemplate 技术栈，前端基于 Vue 3.5 + Arco Design Vue + Pinia + Vue Router + Tiptap + ECharts + Axios + SCSS 技术栈。

## 一、商品管理模块

### 1.1 模块概述

商品管理模块是平台的核心基础模块，承担商品的全生命周期管理，包括商品发布、审核、上架展示、编辑更新、下架删除以及商品统计等功能。该模块与订单交易、收藏、评价、运营后台等模块紧密关联，是整个平台业务流转的起点。

### 1.2 业务逻辑分析

商品管理模块的核心业务逻辑围绕商品状态机展开：

**商品状态机定义：**

```
PENDING_REVIEW（待审核） ──审核通过──→ APPROVED（已审核/上架）
PENDING_REVIEW（待审核） ──审核拒绝──→ REJECTED（已拒绝）
APPROVED（已审核/上架） ──卖家下架──→ OFF_SHELF（已下架）
```

**核心业务规则：**

1. **发布规则**：仅具有 SELLER 角色的用户可发布商品，商品创建后自动进入 `PENDING_REVIEW` 状态
2. **审核规则**：运营人员审核商品，通过后状态变为 `APPROVED`，拒绝时需填写拒绝原因
3. **上架展示**：仅 `APPROVED` 状态的商品对买家可见，出现在商品列表和搜索结果中
4. **编辑规则**：卖家只能编辑自己的商品，编辑后商品状态不变
5. **下架规则**：卖家可主动下架已上架商品，下架后状态变为 `OFF_SHELF`，并触发通知运营人员
6. **删除规则**：卖家可删除自己的商品，执行物理删除
7. **购买约束**：只有 `APPROVED` 状态的商品才可被购买

### 1.3 产品逻辑分析

**用户视角：**

- **卖家**：进入"发布商品"页面填写标题、价格、描述、图片、分类、成色、校区等信息 → 提交后进入待审核状态 → 在"我的商品"页面查看商品状态（待审核/已上架/已下架/已拒绝）→ 可编辑、下架或删除商品
- **买家**：在商品列表页浏览已上架商品 → 可通过关键词搜索、分类筛选、成色筛选、校区筛选、价格排序等方式查找商品 → 点击进入商品详情页查看完整信息 → 可收藏、加入购物车或直接购买

**产品设计亮点：**

1. **瀑布流布局**：商品列表采用 MasonryLayout 瀑布流组件，适配不同尺寸的商品图片，提升浏览体验
2. **多维筛选**：支持关键词、分类、成色、校区、排序方式（最新/价格升序/价格降序）的组合筛选
3. **热度推荐**：基于浏览量、点击量、收藏量加权计算热度评分，提供热门商品推荐
4. **商品详情丰富度**：详情页展示商品基本信息、卖家信息（联系方式、已售数量、评分）、统计数据（浏览/点击/收藏）、评价列表
5. **标签化展示**：通过 ConditionTag（成色标签）、PriceTag（价格标签）、ProductCard（商品卡片）等组件实现信息的标签化、结构化展示

### 1.4 技术实现分析

#### 1.4.1 后端实现

**Controller 层（ItemController）：**

- 路径：`/api/items`
- 采用 `@PreAuthorize` 注解实现方法级权限控制，创建、更新、删除、下架操作要求 SELLER 角色
- 使用 Java 17 Record 类定义请求参数（CreateItemRequest、ItemQueryRequest、ItemReviewRequest、MineItemRequest），结合 `@Validated` 注解实现参数校验
- 支持两种查询方式：GET 请求（简单查询）和 POST 请求（复杂筛选条件）
- 商品详情接口自动触发浏览量统计（trackView）

**Service 层（ItemService）：**

- 核心业务逻辑封装，包括卖家验证、分页参数校验、图片URL解析等
- `createItem` 方法：验证卖家存在性 → 获取卖家昵称 → 解析图片URL → 调用 Repository 保存 → 自动初始化统计数据
- `listItemsPaged` 方法：根据筛选条件组合查询，支持 approvedOnly/mine/keyword/category/sort/conditionLevel/campus 等多维度筛选
- `offShelfItem` 方法：验证商品归属 → 更新状态为 OFF_SHELF → 触发通知
- `getItemDetail` 方法：通过多表 JOIN 获取商品详情、统计数据、卖家信息、评价统计

**ItemStatsService：**

- 热度评分算法：`hot_score = click_count × 2.0 + favorite_count × 3.0 + view_count × 0.5`
- 采用 MySQL `ON DUPLICATE KEY UPDATE` 实现原子化的计数器递增操作，避免并发问题
- 支持批量初始化统计数据（batchInitWithRandomStats），用于开发测试阶段

**Repository 层（ItemRepository）：**

- 基于 JdbcTemplate 实现，使用自定义 RowMapper 进行结果集映射
- 定义三种 RowMapper：ROW_MAPPER（基础）、ROW_MAPPER_WITH_STATS（含统计）、DETAIL_ROW_MAPPER（含卖家详情和评价统计）
- 分页查询采用动态 SQL 拼接，根据筛选条件动态添加 WHERE 子句和参数
- 详情查询使用多表 LEFT JOIN（item + item_stats + user_account），子查询获取卖家已售数量和评分

### 1.7 关键代码实现说明

**1. 商品创建——自动初始化统计数据**

商品保存时，通过 `INSERT IGNORE INTO item_stats` 自动创建对应的统计记录，确保每个商品都有统计数据，避免后续查询时出现空值：

```java
public Map<String, Object> save(...) {
    KeyHolder kh = new GeneratedKeyHolder();
    jdbc.update(con -> {
        var ps = con.prepareStatement(
            "INSERT INTO item (...) VALUES (?, ?, ?, ?, ?, 'PENDING_REVIEW', ?, ?, ?, ?)",
            Statement.RETURN_GENERATED_KEYS);
        // ... 参数设置
        return ps;
    }, kh);
    Long id = kh.getKey().longValue();
    // 自动初始化统计记录
    jdbc.update("INSERT IGNORE INTO item_stats (item_id, view_count, click_count, favorite_count, hot_score) VALUES (?, 0, 0, 0, 0.00)", id);
    return findById(id);
}
```

**2. 热度评分——原子化更新**

使用 MySQL 的 `ON DUPLICATE KEY UPDATE` 语法实现原子化的计数器递增和热度评分更新，避免并发场景下的数据不一致：

```java
public void incrementView(Long itemId) {
    String sql = "INSERT INTO item_stats (item_id, view_count, hot_score) VALUES (:itemId, 1, 1.0) "
        + "ON DUPLICATE KEY UPDATE view_count = view_count + 1, hot_score = hot_score + 0.5";
    jdbc.update(sql, Map.of("itemId", itemId));
}
```

**3. 商品详情——多表联合查询**

详情查询通过 LEFT JOIN 关联 item_stats 和 user_account 表，并使用子查询获取卖家已售数量和评分，一次查询获取所有详情数据：

```sql
SELECT i.*, COALESCE(s.view_count, 0) AS view_count,
       COALESCE(s.click_count, 0) AS click_count,
       COALESCE(s.favorite_count, 0) AS favorite_count,
       u.phone AS seller_phone,
       u.campus AS seller_campus,
       (SELECT COUNT(*) FROM orders o WHERE o.seller_id = i.seller_id AND o.status = 'COMPLETED') AS seller_sold_count,
       (SELECT COALESCE(ROUND(AVG(r.rating), 1), 5.0) FROM review r WHERE r.seller_id = i.seller_id AND r.status = 'APPROVED') AS seller_rating,
       (SELECT COUNT(*) FROM review r WHERE r.item_id = i.id AND r.status = 'APPROVED') AS review_count
FROM item i
LEFT JOIN item_stats s ON i.id = s.item_id
LEFT JOIN user_account u ON i.seller_id = u.id
WHERE i.id = ?
```

## 二、订单交易模块

### 2.1 模块概述

订单交易模块是平台的核心业务模块，实现从下单到交易完成的完整交易闭环。该模块涵盖订单创建、支付、发货、确认收货、取消、退款等全流程操作，并通过严格的状态机控制确保交易流程的合法性和一致性。

### 2.2 业务逻辑分析

**订单状态机定义：**

```
PENDING_PAYMENT（待支付） ──支付──→ PAID（已支付）
PENDING_PAYMENT（待支付） ──取消──→ CANCELLED（已取消）
PAID（已支付） ──发货──→ SHIPPED（已发货）
PAID（已支付） ──取消──→ CANCELLED（已取消）
PAID（已支付） ──申请退款──→ REFUNDING（退款中）
SHIPPED（已发货） ──确认收货──→ COMPLETED（已完成）
SHIPPED（已发货） ──申请退款──→ REFUNDING（退款中）
REFUNDING（退款中） ──同意退款──→ REFUNDED（已退款）
REFUNDING（退款中） ──拒绝退款──→ PAID（已支付）
COMPLETED（已完成） → 终态
CANCELLED（已取消） → 终态
REFUNDED（已退款） → 终态
```

**核心业务规则：**

1. **下单规则**：买家不能购买自己的商品；商品必须为 APPROVED 状态；同一买家对同一商品不可重复创建进行中的订单
2. **支付规则**：仅买家可支付，订单必须处于 PENDING_PAYMENT 状态
3. **发货规则**：仅卖家可发货，需填写快递公司和快递单号，订单必须处于 PAID 状态
4. **确认收货**：仅买家可确认收货，订单必须处于 SHIPPED 状态
5. **取消规则**：买卖双方均可取消，仅限 PENDING_PAYMENT 和 PAID 状态
6. **退款规则**：买家可申请退款（PAID/SHIPPED 状态），卖家可同意或拒绝退款；同意退款后状态变为 REFUNDED，拒绝退款后回退到 PAID 状态
7. **退款通知**：买家申请退款时自动通知运营人员

### 2.3 产品逻辑分析

**用户视角：**

- **买家**：浏览商品 → 加入购物车/直接购买 → 填写收货信息 → 创建订单 → 支付 → 等待发货 → 确认收货 → 评价
- **卖家**：收到新订单通知 → 查看订单详情 → 填写快递信息发货 → 等待买家确认 → 处理退款申请（如有）

**产品设计亮点：**

1. **订单号生成**：采用 "ORD + 时间戳 + 随机数" 格式，确保唯一性和可读性
2. **角色感知列表**：我的订单页面根据用户角色（买家/卖家/双重角色）智能展示对应订单
3. **状态筛选**：支持按订单状态筛选，方便用户快速定位特定状态的订单
4. **订单金额**：自动计算 total_amount = price × quantity
5. **商品快照**：订单中保存商品标题、图片等快照信息，即使商品后续修改也不影响订单展示

### 2.4 技术实现分析

#### 2.4.1 后端实现

**Controller 层（OrderController）：**

- 路径：`/api/orders`
- 类级别 `@PreAuthorize("isAuthenticated()")` 确保所有订单操作需登录
- 运营端订单列表要求 OPS 角色
- 退款审批要求 OPS 或 SELLER 角色
- 使用 Record 类定义请求参数：CreateOrderRequest（itemId/quantity/receiverName/receiverPhone/receiverAddress）、ShipRequest（expressCompany/expressNo）

**Service 层（OrderService）：**

- **状态机实现**：使用静态 Map 定义合法的状态转换（STATUS_TRANSITIONS），`canTransition` 方法校验状态转换合法性
- **权限校验**：`validateOrderAccess`（买卖双方均可）、`validateOrderBuyerAccess`（仅买家）、`validateOrderOwnership`（仅卖家）三种权限校验方法
- **防重复下单**：`hasActiveOrder` 方法检查买家是否已有该商品的进行中订单（PENDING_PAYMENT/PAID/SHIPPED）
- **角色感知查询**：`getMinePaged` 方法根据用户角色（是否同时为买家和卖家）决定查询范围，双重角色时合并查询结果并按时间排序

**Repository 层（OrderRepository）：**

- 订单号生成：`"ORD" + yyyyMMddHHmmss + 随机3位数`
- 支持多维度分页查询：按买家、按卖家、按状态、按关键词
- 运营端查询支持多字段模糊搜索（order_no/item_title/buyer_name/seller_name）
- 丰富的统计方法：按日期范围、按状态、按卖家等多维度统计

**1. 状态机校验**

使用静态 Map 定义合法的状态转换，所有状态变更操作前必须通过 `canTransition` 校验：

```java
private static final Map<String, List<String>> STATUS_TRANSITIONS = Map.of(
    "PENDING_PAYMENT", List.of("PAID", "CANCELLED"),
    "PAID", List.of("SHIPPED", "CANCELLED", "REFUNDING"),
    "SHIPPED", List.of("COMPLETED", "REFUNDING"),
    "REFUNDING", List.of("REFUNDED", "PAID"),
    "COMPLETED", List.of(),
    "CANCELLED", List.of(),
    "REFUNDED", List.of()
);

private boolean canTransition(String currentStatus, String nextStatus) {
    List<String> allowed = STATUS_TRANSITIONS.get(currentStatus);
    return allowed != null && allowed.contains(nextStatus);
}
```

    boolean isBuyer = roles.contains("BUYER");

        rows.addAll(sellerRows);
        rows.sort((a, b) -> String.valueOf(b.getOrDefault("createdAt", "")).compareTo(String.valueOf(a.getOrDefault("createdAt", ""))));
        rows = rows.stream().limit(pageSize).toList();
    } else if (isSeller) {
        rows = orderRepository.findBySellerIdPaged(userId, status, pageNo, pageSize);
    } else {
        rows = orderRepository.findByBuyerIdPaged(userId, status, pageNo, pageSize);
    }
}

### 3.1 模块概述

购物车模块为买家提供商品暂存和批量管理功能，支持添加商品、修改数量、选中/取消选中、批量操作和清空购物车等操作，是下单交易的前置环节。

```java
public Map<String, Object> addToCart(Long userId, Long itemId, int quantity) {
    var existingOpt = cartRepository.findByUserIdAndItemId(userId, itemId);
    if (existingOpt.isPresent()) {
        Map<String, Object> existing = existingOpt.get();
        int newQuantity = (int) existing.get("quantity") + quantity;
        if (newQuantity > 99) newQuantity = 99;
        cartRepository.updateQuantity((Long) existing.get("id"), newQuantity);
        return Map.of("code", 200, "message", "已更新购物车数量", "data", cartRepository.findById((Long) existing.get("id")).orElseThrow());
    }
    Map<String, Object> cartItem = cartRepository.create(userId, itemId, quantity, true);
    return Map.of("code", 200, "message", "已加入购物车", "data", cartItem);
}
```

**2. 购物车列表——关联商品信息与金额计算**

```java
public Map<String, Object> getCartList(Long userId) {
    List<Map<String, Object>> cartItems = cartRepository.findByUserId(userId);
    List<Map<String, Object>> result = new ArrayList<>();
    int totalAmount = 0;
    for (Map<String, Object> cart : cartItems) {
        Long itemId = (Long) cart.get("itemId");
        var item = itemRepository.findById(itemId);
        if (item != null) {
            Map<String, Object> enrichedItem = new HashMap<>(cart);
            enrichedItem.put("item", item);
            if ((Boolean) cart.get("selected")) {
                totalAmount += (int) item.get("price") * (int) cart.get("quantity");
            }
            result.add(enrichedItem);
        }
    }
    return Map.of("code", 200, "data", result, "totalAmount", totalAmount);
}
```

## 五、评价模块

### 5.1 模块概述

评价模块实现交易完成后的评价功能，包括买家评价、卖家回复、评价审核等环节。评价与订单和商品关联，是交易闭环的最后一环，同时为其他买家提供购买参考。

### 5.2 业务逻辑分析

**评价状态机定义：**

```
PENDING（待审核） ──审核通过──→ APPROVED（已通过）
PENDING（待审核） ──审核拒绝──→ REJECTED（已拒绝）
```

**核心业务规则：**

1. **评价条件**：仅 COMPLETED 状态的订单可评价，且每个订单只能评价一次
2. **评价内容**：包含评分（1-5星）、文字内容、图片（可选）
3. **评价来源**：支持两种评价方式——通过订单评价（需校验订单归属和状态）和直接对商品评价（无需订单关联）
4. **审核机制**：评价提交后进入 PENDING 状态，需运营审核通过后才公开展示
5. **卖家回复**：卖家或运营人员可对评价进行回复
6. **评分统计**：自动计算商品平均评分和评分分布

### 5.3 产品逻辑分析

**用户视角：**

- **买家**：订单完成后在订单详情页点击"评价" → 填写评分和内容（支持 Tiptap 富文本编辑器）→ 提交评价 → 在"我的评价"页面查看评价状态
- **卖家**：收到评价通知 → 查看评价详情 → 可回复评价
- **运营**：在审核页面查看待审核评价 → 通过或驳回评价

**产品设计亮点：**

1. **富文本编辑**：使用 Tiptap 3.x 富文本编辑器，支持格式化文本和图片插入
2. **1-5星评分**：直观的星级评分组件
3. **评分分布**：展示各星级评价数量分布，帮助买家快速了解商品口碑
4. **评价统计**：自动计算平均评分，展示在商品详情页

    String currentSessionId = sessionRepository.createOrReuseSession(sessionId, userId);
    sessionRepository.updateSessionTime(currentSessionId);
    
    // 检索知识库
    var knowledgeChunks = knowledgeRepository.search(message);
    List<String> references = knowledgeChunks.stream()
        .map(chunk -> chunk.get("title") + ": " + chunk.get("content"))
        .toList();
    
    String referencesJson = objectMapper.valueToTree(references).toString();
    messageRepository.save(currentSessionId, "user", message, referencesJson);
    
    // 调用 AI
    String answer = callRealAI(message, role, references);
    messageRepository.save(currentSessionId, "assistant", answer, null);
    
    return Map.of("code", 200, "sessionId", currentSessionId, "reply", answer, "references", references);
}

**1. 运营独立认证体系**

运营账号使用独立的 ops_account 表和独立的登录接口，与普通用户体系完全隔离：

```java
public Map<String, Object> opsLogin(String username, String password) {
    var accountOpt = opsAccountRepository.findByUsername(username);
    if (accountOpt.isEmpty()) throw new IllegalArgumentException("运营账号不存在");
    var account = accountOpt.get();
    if (!"ACTIVE".equals(account.getStatus())) throw new IllegalArgumentException("账号已被禁用");
    if (!passwordEncoder.matches(password, account.getPassword())) throw new IllegalArgumentException("密码错误");
    
    Long opsId = account.getId();
    List<String> roles = account.getRolesList();
    String token = jwtUtil.generateToken(username, roles, opsId);
    
    Map<String, Object> response = new HashMap<>();
    response.put("token", token);
    response.put("tokenType", "Bearer");
    // ... 返回用户信息（不含密码）
    return response;
}
```

**2. 销售趋势——按日聚合**

循环查询每日数据，构建时间序列趋势数据：

```java
public Map<String, Object> getTrend(Long sellerId, int days) {
    LocalDateTime now = LocalDateTime.now();
    List<Map<String, Object>> trendData = new ArrayList<>();
    DateTimeFormatter formatter = DateTimeFormatter.ofPattern("MM-dd");
    
    for (int i = days - 1; i >= 0; i--) {
        LocalDate date = now.minusDays(i).toLocalDate();
        LocalDateTime startOfDay = date.atStartOfDay();
        LocalDateTime endOfDay = date.plusDays(1).atStartOfDay();
        int sales = orderRepository.sumTotalAmountBySellerAndStatusAndTimeRange(sellerId, "COMPLETED", startOfDay, endOfDay);
        int orders = orderRepository.countBySellerAndStatusAndTimeRange(sellerId, "COMPLETED", startOfDay, endOfDay);
        trendData.add(Map.of("date", date.format(formatter), "sales", sales, "orders", orders));
    }
    return Map.of("code", 200, "data", trendData);
}
```

## 十、核心模块间协作关系

### 10.1 商品→订单→评价完整业务流程

这是平台最核心的业务闭环，描述了从商品发布到交易完成评价的完整流程：

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  卖家    │     │  商品    │     │  订单    │     │  交易    │     │  评价    │
│  发布    │────→│  审核    │────→│  创建    │────→│  完成    │────→│  评价    │
│  商品    │     │  上架    │     │  支付    │     │  收货    │     │  审核    │
└──────────┘     └──────────┘     └──────────┘     └──────────┘     └──────────┘
     │                │                │                │                │
     ▼                ▼                ▼                ▼                ▼
  PENDING_        APPROVED       PENDING_           SHIPPED          PENDING
  REVIEW          (上架)         PAYMENT            (已发货)          (待审核)
     │                │                │                │                │
     ▼                ▼                ▼                ▼                ▼
  运营审核 ────→  买家浏览 ────→  买家支付 ────→  卖家发货 ────→  买家确认 ────→  买家评价 ────→  运营审核
  通过/拒绝       加入购物车       (模拟支付)       填写快递信息     收货          1-5星评分      通过/拒绝
                  收藏商品                                         (COMPLETED)    富文本内容
                                                                  ↓
                                                             卖家回复评价
```

**详细流程说明：**

1. **商品发布与审核**：卖家发布商品 → 商品进入 PENDING_REVIEW 状态 → 运营审核 → 通过则 APPROVED（上架），拒绝则 REJECTED
2. **商品浏览与互动**：买家浏览已上架商品 → 可收藏、加入购物车、查看详情 → 浏览/点击/收藏行为自动记录到 item_stats
3. **订单创建与支付**：买家下单 → 订单进入 PENDING_PAYMENT 状态 → 买家支付 → 订单进入 PAID 状态
4. **发货与收货**：卖家发货（填写快递信息）→ 订单进入 SHIPPED 状态 → 买家确认收货 → 订单进入 COMPLETED 状态
5. **评价与审核**：买家对已完成订单评价 → 评价进入 PENDING 状态 → 运营审核 → 通过则 APPROVED（公开展示），拒绝则 REJECTED → 卖家可回复评价

### 10.2 圈子→审核流程

2. **订单监管**：运营可查看所有订单、审批退款申请、查看订单趋势和状态分布
3. **圈子监管**：运营可审核帖子和评论、查看待审核数量
4. **评价监管**：运营可审核评价（通过/驳回/删除）、回复评价、查看待审核数量
5. **用户监管**：运营可修改用户角色、禁用/启用用户、查看供方（卖家）和需方（买家）统计

### 10.5 安全架构与认证体系

系统采用双轨认证体系，普通用户和运营人员使用独立的认证通道：

```
┌──────────────────────────────────────────────────────────┐
│                    Spring Security                        │
│                                                          │
│  ┌──────────────────────────────────────────────────┐   │
│  │              JwtAuthenticationFilter              │   │
│  │  解析 JWT Token → 设置 SecurityContext           │   │
│  └──────────────────────┬───────────────────────────┘   │
│                         │                                │
│         ┌───────────────┼───────────────┐               │
│         │               │               │               │
│         ▼               ▼               ▼               │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐       │
│  │ BUYER 角色 │  │ SELLER角色 │  │  OPS 角色  │       │
│  │ (user_     │  │ (user_     │  │ (ops_      │       │
│  │  account)  │  │  account)  │  │  account)  │       │
│  └────────────┘  └────────────┘  └────────────┘       │
│                                                          │
│  认证入口：                                               │
│  • /api/auth/login    → 普通用户登录                     │
│  • /api/auth/register → 普通用户注册                     │
│  • /api/auth/ops/login → 运营账号登录                    │
│                                                          │
│  公开接口：                                               │
│  • GET /api/items, /api/items/* → 商品浏览               │
│  • GET /api/circle/** → 圈子浏览                         │
│  • /api/items/hot, /api/items/*/track-* → 热门和统计     │
└──────────────────────────────────────────────────────────┘
```

**安全设计要点：**

1. **无状态会话**：SessionCreationPolicy.STATELESS，基于 JWT Token 认证
2. **CSRF 禁用**：前后端分离架构，使用 Token 认证而非 Cookie
3. **CORS 配置**：允许所有来源（开发环境），生产环境应限制具体域名
4. **方法级权限**：使用 `@PreAuthorize` 注解实现细粒度权限控制
5. **密码加密**：BCrypt 算法加密存储密码
6. **双表隔离**：user_account 和 ops_account 物理隔离，防止权限越权
