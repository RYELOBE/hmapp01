# 4 系统基础模块设计与实现

## 4.1 系统流程

校园二手交易平台整体业务流程围绕买家、卖家和运营三类角色展开。用户通过浏览器访问前端Vue 3应用，首次进入系统显示首页，包含商品轮播图、热门商品推荐和系统公告信息。用户可通过导航栏进入登录页面，支持普通用户注册登录和运营人员独立登录入口。登录成功后，系统通过JWT无状态认证机制验证用户身份，根据用户角色（BUYER/SELLER/OPS）动态分配页面访问权限。

系统核心数据流为：卖家发布商品→运营审核→商品上架→买家浏览/搜索→加入购物车/收藏→创建订单→支付→卖家发货→买家确认收货→提交评价→运营审核评价→评价展示。校园圈子数据流为：用户发布帖子→运营审核→帖子展示→其他用户点赞/评论。所有操作通过RESTful API与Spring Boot后端交互，数据持久化至MySQL数据库。

## 4.2 基础功能模块设计概述

根据需求分析，对基础功能模块进行如下设计：

**（1）认证授权设计**

系统提供用户注册、登录和角色管理功能，支持普通用户和运营人员双入口登录。用户注册时需填写用户名、密码、昵称、手机号和校区信息，密码经BCrypt加密后存储。登录时系统验证账号密码，验证通过后生成JWT令牌返回给前端，令牌包含用户ID、用户名和角色信息，有效期24小时。前端通过路由守卫校验用户角色权限，无权限访问时跳转403页面。运营人员通过独立接口登录，使用ops_account表独立于user_account表进行身份验证。

**（2）文件上传设计**

系统提供图片上传功能，主要用于商品发布时上传商品图片、校园圈子发布时上传帖子图片、评价提交时上传评价图片。文件类型限制为image/jpeg、image/png、image/gif、image/webp，文件大小限制为5MB。文件采用Base64编码存储策略，便于前端直接使用data URI展示，减少额外HTTP请求。上传文件信息存储到uploaded_file表，包含原始文件名、存储文件名、文件路径、文件大小、内容类型、Base64数据、上传者ID等字段。

**（3）数据字典设计**

系统提供枚举数据动态加载功能，包括用户状态、角色、审核状态、商品状态、订单状态、评价状态、成色选项、支付方式、交易方式、消息类型、优先级、权限列表等12类字典选项。字典数据从数据库字典表查询返回，前端通过字典接口获取筛选选项，实现配置化的状态管理。前端同时定义静态常量作为补充，包括商品状态、订单状态、商品分类、成色、支付方式、用户类型、交易方式等。

**（4）消息通知设计**

站内消息分为系统通知、交易消息、审核消息、互动消息四类，分别对应系统公告、订单状态变更、审核结果通知、点赞评论通知。每条通知包含id、userId、type、title、content、isRead、priority、createdAt字段。Header显示未读消息数量角标，点击展开最近消息面板。支持单条标记已读、批量标记已读、全部已读和删除操作。业务操作触发时自动生成通知，如商品审核通过后向卖家发送通知，订单状态变更时向买卖双方发送通知。

**（5）收货地址设计**

系统支持买家管理收货地址信息，用于订单创建时填写收货地址。address表包含id、userId、receiverName、receiverPhone、province、city、district、detailAddress、postalCode、isDefault、createdAt、updatedAt字段。默认地址采用"先清后设"策略：用户设置默认地址时，先将该用户所有地址的isDefault设为false，再将目标地址设为true。首次添加地址时自动设为默认地址。

**（6）UI界面设计**

系统前端界面采用响应式布局设计，适配桌面端和移动端设备。定义完整的视觉规范系统，包括色彩系统（10级主色阶、4类功能色、6级灰阶）、字体规范（9级字号）、间距规范（8级间距）、圆角规范（5级）、阴影规范（4级）。运营后台采用独立主题，深蓝白色调设计系统，深色侧边栏背景，定义多个Mixin统一运营页面样式，4级响应式断点适配不同屏幕尺寸。

## 4.3 基础功能模块具体实现

### 4.3.1 认证授权设计与实现

后端采用Spring Security框架结合JJWT库实现JWT无状态认证。SecurityConfig配置类定义HTTP请求权限规则，公开登录、注册、商品列表、圈子列表、字典接口，其他接口需认证访问。JwtAuthenticationFilter继承OncePerRequestFilter，从Authorization请求头提取Bearer Token，使用JwtUtil解析验证，提取username、userId、roles信息，构建UsernamePasswordAuthenticationToken设置到SecurityContext。

AuthService处理用户登录验证，调用UserRepository查询用户信息，使用BCryptPasswordEncoder验证密码，验证通过后调用JwtUtil.createToken()生成JWT令牌。用户注册时，密码经BCrypt加密后存储到user_account表。运营人员登录使用独立接口，调用OpsAuthService验证ops_account表数据，生成运营专用Token存储到独立的localStorage key。

前端auth store使用Pinia状态管理，定义token、user、roles三个状态。hydrate方法从localStorage读取缓存的Token和用户信息，isJWTToken验证Token格式，isTokenExpired调用jwt.js工具类检查过期时间。路由守卫beforeEach拦截路由跳转，白名单直接放行，其他路由检查Token存在性和有效性，根据meta.roles校验用户角色权限。Axios请求拦截器为每个请求注入Authorization头，响应拦截器捕获401状态码自动清除Token并跳转登录页。

### 4.3.2 文件上传设计与实现

后端UploadController提供POST /api/upload接口，接收multipart/form-data格式文件上传请求。upload方法通过CurrentUserService获取当前登录用户ID作为上传者标识，调用UploadService.upload()处理文件存储逻辑。文件类型校验限制为image/jpeg、image/png、image/gif、image/webp，文件大小限制为5MB。文件重命名采用UUID策略避免冲突，原始文件名、存储文件名、文件路径、文件大小、内容类型、Base64数据等信息存储到uploaded_file表。文件以Base64编码格式存储，便于前端直接使用data URI展示。

前端ImageUploader组件提供v-model双向绑定，custom-request属性覆盖默认上传行为，调用items service发起文件上传请求。上传成功后返回文件URL，组件预览图片并支持删除操作。商品发布页面PublishItem.vue和圈子发布页面CirclePublish.vue均集成ImageUploader组件实现图片上传功能。

### 4.3.3 数据字典设计与实现

后端DictController提供GET /api/dict/options接口，从数据库字典表查询枚举数据返回给前端。字典数据包含code、name、value三个字段，支持分组返回。前端enums.js定义懒加载缓存机制，首次调用时从接口获取数据并缓存到内存，后续调用直接返回缓存数据，减少网络请求。

系统定义12类字典选项：用户状态（ACTIVE/DISABLED）、用户角色（BUYER/SELLER/OPS）、审核状态（PENDING/APPROVED/REJECTED）、商品状态（PENDING_REVIEW/APPROVED/REJECTED/OFF_SHELF）、订单状态（PENDING_PAYMENT/PAID/SHIPPED/COMPLETED/CANCELLED/REFUNDING/REFUNDED）、评价状态（PENDING/APPROVED/REJECTED）、成色选项（全新/几乎全新/轻微使用痕迹/明显使用痕迹）、支付方式（微信/支付宝/银行卡）、交易方式（面交/邮寄/自取）、消息类型（SYSTEM/TRANSACTION/REVIEW/INTERACTION）、优先级（LOW/MEDIUM/HIGH/URGENT）、权限列表（view_items/manage_items/manage_orders等）。前端constants.js定义静态常量作为补充。

### 4.3.4 消息通知设计与实现

后端NotificationController提供通知列表、未读计数、最近通知、标记已读、批量标记已读、全部标记已读、删除通知、发送通知等接口。NotificationServiceImpl实现业务逻辑，支持四种消息类型：SYSTEM（系统通知，如审核结果通知）、TRANSACTION（交易消息，如订单状态变更）、REVIEW（审核消息，如评价审核通知）、INTERACTION（互动消息，如帖子点赞评论）。每条通知包含id、userId、type、title、content、isRead、priority、createdAt字段。

前端MessageCenter组件集成到Header导航栏，点击展开下拉面板显示最近5条未读消息，Header显示未读数量角标。MessageList页面展示完整消息列表，支持按类型筛选、按时间排序、单条标记已读、批量标记已读、全部已读和删除操作。业务操作触发时自动生成通知，如商品审核通过后向卖家发送通知，订单状态变更时向买卖双方发送通知。

### 4.3.5 收货地址设计与实现

后端AddressController提供收货地址CRUD接口，包括地址列表查询、默认地址查询、地址详情查询、新增地址、更新地址、删除地址、设置默认地址等接口。AddressService处理业务逻辑。address表包含id、userId、receiverName、receiverPhone、province、city、district、detailAddress、postalCode、isDefault、createdAt、updatedAt字段。默认地址采用"先清后设"策略：用户设置默认地址时，先将该用户所有地址的isDefault设为false，再将目标地址设为true。首次添加地址时自动设为默认地址。

前端AddressList页面展示用户收货地址列表，支持新增、编辑、删除操作。AddressCard组件展示单个地址信息，显示联系人、电话、省市区、详细地址，默认地址显示蓝色标签。EditAddressModal弹窗组件集成省市区级联选择器，用户选择省份后动态加载城市列表，选择城市后加载区县列表。下单时OrderConfirm页面调用地址列表接口，用户选择或新增收货地址后提交订单。

## 4.4 基础UI界面设计与实现

### 4.4.1 UI界面设计

**（1）登录界面**

登录页面提供用户名和密码输入框、记住密码选项、登录按钮和注册入口链接。页面布局简洁，居中对齐，背景色为浅灰色。输入框带图标提示，密码输入框支持显示/隐藏切换。登录按钮采用主色调#165DFF，hover时颜色加深。

**（2）注册界面**

注册页面包含用户名、密码、确认密码、昵称、手机号、校区选择等表单字段，支持表单实时验证。用户名要求6-20位字母数字组合，密码要求至少8位且包含大小写字母和数字。校区选择使用下拉菜单，列出所有支持的大学校区。注册按钮在表单验证通过后启用。

**（3）首页界面**

用户首次进入系统时显示首页，包含顶部导航栏、商品轮播图、热门商品推荐区和系统公告区。导航栏包含Logo、主菜单（首页/商品/圈子/AI助手）、搜索框、购物车图标、消息图标和用户头像下拉菜单。轮播图展示平台活动或精选商品，热门商品区以瀑布流布局展示热度评分最高的商品。

**（4）个人中心界面**

个人中心页面展示用户头像、昵称、角色标签和基本资料，支持编辑个人资料、修改密码、管理收货地址、查看我的订单、我的收藏和我的评价等快捷入口。页面采用卡片式布局，左侧为用户信息卡片，右侧为功能入口网格。

**（5）运营后台界面**

运营后台采用深色侧边栏导航，主内容区采用卡片式布局。数据仪表盘页面展示统计卡片（今日订单数、今日完成数、今日金额、总金额）和趋势图表（订单趋势折线图、商品分类统计饼图、订单状态分布柱状图）。审批工作台页面整合商品、评价、帖子三类待审核内容的统一列表，支持批量审核操作。

### 4.4.2 UI界面实现

前端基于Vue 3 Composition API和script setup语法构建组件。Header.vue组件使用Arco Design的a-menu、a-badge、a-dropdown组件实现导航栏，通过Pinia auth store获取当前用户信息，路由守卫控制菜单显示。LoginView.vue组件使用a-form、a-input、a-button组件构建登录表单，调用auth service发起登录请求，成功后存储Token到localStorage并跳转首页。

Register.vue组件使用a-form表单组件构建注册表单，包含a-input、a-select、a-button等子组件，表单验证规则定义在formRules对象中，提交时调用auth service发起注册请求。Profile.vue页面展示用户基本信息，使用a-avatar组件显示头像，a-descriptions组件展示用户资料，a-tabs组件切换不同功能区域。

运营后台OpsLayout.vue组件采用a-layout布局，侧边栏使用a-menu组件定义菜单项，主内容区使用a-layout-content。数据仪表盘EnhancedDashboard.vue使用OpsBarChart、OpsDonutChart、OpsLineChart组件展示统计图表，底层基于vue-echarts封装ECharts实例。所有运营页面使用ops-card、ops-page-container、ops-toolbar等Mixin统一样式风格，确保界面一致性。
